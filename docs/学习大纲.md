### 一、技术栈选型（唯一推荐方案）

为了兼顾**电脑/平板/手机**三端运行，且快速开发上位机，**Flutter** 依然是你的不二之选，但架构需要升级：

1.  **前端框架**：**Flutter **(Dart)
    *   **理由**：一套代码编译为 Windows (PC上位机), Android (平板/手机), macOS。完美符合“运行在电脑or平板or手机均可”的需求。
    *   **优势**：绘图能力强（`fl_chart`库画ECG波形和HRV散点图非常流畅），UI现代化。

2.  **核心算法层**：**C++ **(通过 FFI 调用)
    *   **理由**：HRV算法（滤波、R波检测、频域分析）计算量大，Dart处理实时流可能卡顿。你用C++写算法库，编译成 `.dll` (Windows) 和 `.so` (Android)，Flutter直接调用。
    *   **战略意义**：这是你作为软工的核心竞争力，也是答辩时的技术亮点（“高性能异构计算”）。

3.  **通信协议**：**Bluetooth Low Energy **(BLE)
    *   **理由**：穿戴式心电设备和植入式DBS系统必然使用BLE传输数据。
    *   **库**：`flutter_blue_plus` (目前最稳定、功能最全的Flutter蓝牙库)。

4.  **数据可视化**：
    *   **波形**：`fl_chart` (折线图) 或自定义 `CustomPainter` (为了达到医疗级的高刷新率波形，建议学习CustomPainter)。
    *   **庞加莱图/频谱图**：`fl_chart` (散点图) + C++计算FFT。

### 二、分阶段学习与执行规划（以4个月为例）

假设比赛/结题在4个月后，我们将时间划分为四个冲刺阶段。

#### 📅 第一阶段：基础搭建与通信打通（第1-3周）
**目标**：环境配好，App能跑，能通过蓝牙收到模拟的心跳数据并显示波形。

*   **第1周：Flutter 极速入门**
    *   **学习内容**：
        *   Dart 语言基础（变量、函数、异步 `async/await`、Stream流）。**重点掌握 Stream**，因为传感器数据是连续流。
        *   Flutter 布局（Row, Column, Stack, Container）。
        *   状态管理：推荐使用 **Provider** 或 **Riverpod**（简单易懂，适合中小项目）。
    *   **产出**：一个能显示“连接按钮”和“空白图表区域”的App界面。
*   **第2周：蓝牙通信 **(BLE)
    *   **学习内容**：
        *   理解 BLE 概念：Service, Characteristic, Notify, Write。
        *   使用 `flutter_blue_plus` 扫描设备、连接、订阅数据流。
        *   **难点攻克**：如何处理高频数据包（ECG采样率通常250Hz-500Hz），避免UI卡顿（使用 `Isolate` 隔离线程处理数据解析）。
    *   **产出**：App能连接到一个蓝牙模拟器（手机装个nRF Connect模拟发送数据），并在控制台打印出接收到的十六进制数据。
*   **第3周：波形绘制与C++接口预研**
    *   **学习内容**：
        *   使用 `CustomPainter` 绘制动态心电图（ECG）。**不要直接用现成的Chart库画高频波形，会卡**，要自己写绘制逻辑（维护一个固定长度的数组，滚动更新）。
        *   配置 C++ FFI 环境，写一个 "Hello World" C++ 函数并在Flutter中调用成功。
    *   **产出**：界面上有一条随蓝牙数据跳动的绿色波形线（哪怕还没滤波，是_raw_数据）。

#### 📅 第二阶段：核心算法与多模态融合（第4-7周）
**目标**：从Raw数据中算出HRV指标，并能接收DBS系统的脑电数据，实现“双模态”展示。

*   **第4-5周：C++ HRV算法移植**
    *   **任务**：
        *   找生医工学妹要算法公式（或MATLAB代码）。
        *   用 C++ 实现：
            1.  **预处理**：带通滤波（0.5-40Hz），去除基线漂移。
            2.  **R波检测**：Pan-Tompkins算法（经典，必须实现）。
            3.  **指标计算**：时域（SDNN, RMSSD）、频域（LF, HF, LF/HF - 需要FFT，可用 `kissfft` 库或自己写）。
        *   封装成动态库，供Flutter调用。
    *   **产出**：App界面上不仅有心电波形，还能实时显示：`HR: 75 bpm`, `SDNN: 45ms`, `Stress Level: High`。
*   **第6周：对接DBS系统**（多模态关键）
    *   **任务**：
        *   联系做DBS硬件的师兄，获取他们的**蓝牙通信协议文档**。
        *   在App中增加第二个蓝牙连接通道（或在一个连接中区分不同Service）。
        *   接收脑电信号（LFP, 局部场电位）或刺激状态反馈。
    *   **产出**：App能同时显示两路波形（上面是ECG，下面是LFP），或者显示“当前脑部状态：抑郁发作期”。
*   **第7周：闭环逻辑实现**（软件层面的“智能”）
    *   **任务**：
        *   编写决策逻辑（可以在C++层，也可以在Dart层）：
        *   `IF (HRV_LF_HF_Ratio > Threshold) AND (Beta_Band_Power > Threshold) THEN Trigger_Stimulation()`
        *   实现“一键下发刺激参数”功能（通过BLE Write指令发给DBS硬件）。
    *   **产出**：演示视频：当模拟数据出现“抑郁特征”时，App自动弹出警告，并自动/手动发送指令开启DBS刺激。

### 三、给你的特别战术建议

1.  **关于“闭环”的软件定义**：
    *   真正的医疗闭环可能需要毫秒级响应，这通常在嵌入式端（硬件内部）完成。
    *   **你的策略**：在软件层面实现"**监测 - 评估 - 干预建议 - 人工/自动确认 - 执行**"的半自动闭环。
    *   **话术**：“我们的上位机系统负责高阶的情绪状态融合评估（多模态），并将决策指令下发给植入端执行，实现了‘云 - 边 - 端’协同的闭环治疗。” —— 这样既规避了无线传输延迟的硬伤，又拔高了系统架构。

2.  **如何利用队友**：
    *   **生医工学妹**：让她负责**数据标注**和**算法验证**。你写好C++代码后，给她一组标准数据，让她算出来的结果和你代码跑出来的一致，她就在申报书里写“算法经过严格验证”。
    *   **计算机同学**：如果他擅长后端，让他帮你搭一个简单的**本地数据库**（SQLite）或**云端同步**功能，记录患者长期的HRV变化趋势。如果他也只会前端，那就让他负责UI美化，你专注逻辑和算法。
    *   **师兄**：一定要拿到**详细的通信协议文档**（字节定义、校验位、指令集）。这是你开发的基石。

3.  **避坑指南**：
    *   **不要试图自己发明HRV算法**：直接用经典的 Pan-Tompkins 和 Welch 法。
    *   **不要过度追求UI酷炫**：医疗软件讲究“严谨、清晰、专业”。白底黑字/绿字，线条清晰，数据准确最重要。
    *   **蓝牙调试是噩梦**：尽早开始调试蓝牙，预留足够的时间处理“连不上”、“数据乱码”、“断连”等问题。
