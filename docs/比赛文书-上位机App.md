# 2.4 上位机 App 软件设计

## 2.4.1 功能定位与架构

上位机 App 是本作品闭环 DBS 多模态神经调控系统的重要软件成果之一，承担用户登录、对象档案管理、BLE 设备连接、ECG 与 DBS-LFP 实时数据展示、HRV 胸环控制、压力状态分析、DBS 刺激交互、离线数据测试和历史记录归档等人机交互任务。系统主要面向科研测试、实验联调、参数验证、数据复盘和故障诊断等场景使用。实际运行时，DBS 端负责最终刺激执行与硬件安全保护；上位机主要用于可视化监测、参数下发、状态反馈、安全干预和数据分析。

本 App 采用前后端分离的本地架构。前端基于 Flutter 实现跨平台界面，负责用户登录与对象档案切换、BLE 设备管理、实时 BLE 数据解析、ECG/DBS-LFP 波形绘制、HRV 指标展示、压力状态可视化、HRV 胸环标定流程控制、DBS 刺激启停与参数同步、离线测试和历史记录页面；后端基于 Python FastAPI 提供本地计算服务，负责 `.mat` 离线数据解析、ECG 滤波结果读取、R 峰检测、HRV 指标计算和分析结果生成。实时 DBS 数据来自 BLE Notify/StreamData，解析和绘图均在 Flutter 前端本地完成，不经过 FastAPI 后端；后端只参与离线文件分析和计算报告生成。数据管理层按用户与对象档案维护本地历史记录库，将采集会话、ECG 片段、HRV 指标、压力状态、DBS 参数和设备状态关联到对应对象，便于实验人员按受试者或测试对象维度进行复盘。

实时硬件通信部分通过 BLE 完成。KT6368A HRV 胸环已完成数据接入，支持 ECG 波形、R 峰、HRV 指标、电量与压力状态上报，并支持基线标定、应激诱导、取消、重置和清除模型等控制命令。DBS 侧作为闭环调控对象接入 App，已支持 BLE 连接、状态解析、LFP 流数据接入、刺激参数查询与配置、刺激启停、压力分数发送和 E-STOP 交互。对于刺激强度、频率和脉宽等参数，App 软件侧可完成参数编辑、BLE 指令下发和状态反馈更新；实际刺激是否按该参数执行，由 DBS 固件接收、校验、安全策略和回传状态共同确认。

(1) 用户登录与对象档案。

App 引入用户登录入口和对象档案机制，用于区分研究/测试人员、医生或科研负责人以及患者/受试者档案。系统定位以科研测试为主，因此研究/测试人员是主要操作者，负责连接设备、启动采集、执行标定流程、发送 DBS 指令、导入离线数据和查看历史记录；医生或科研负责人主要负责实验方案确认、参数边界审核和安全决策；患者/受试者在 App 中主要表现为对象档案，用于承载数据归属，而不是默认操作 DBS 的使用者。登录后，系统以用户 ID 和对象档案作为数据归属入口，将实时采集会话、离线分析结果、HRV 指标、压力状态、DBS 参数和设备状态关联到对应对象，避免多名受试者或测试批次的数据混杂。

(2) BLE 设备连接与通信。

App 作为 BLE Central 扫描并连接目标外设，统一管理 HRV 胸环和 DBS 设备连接状态。HRV 胸环按照设备广播名和 Service UUID 进行过滤，订阅 Notify 特征值接收实时 ECG、R 峰、HRV、STR 和电量数据，并通过 Write 特征值下发标定和流程控制命令。DBS 设备通过独立 BLE 服务接入，App 订阅设备通知、流数据和存储数据特征，解析 DBS 设备状态、感知配置、运行状态、刺激参数反馈和 LFP 流数据，同时通过写特征下发压力分数、刺激参数、运行配置和 E-STOP 等命令。界面以设备卡片展示连接状态、电量、温度和数据源状态，便于实验联调时快速判断链路质量。

(3) HRV 胸环控制与压力分析。

HRV 胸环不仅承担数据上报，还承担压力状态评估流程中的主动控制任务。App 可向胸环下发 `CMD:C` 启动 7 分钟基线标定，记录平静状态下的 HRV 基线；下发 `CMD:S` 启动应激诱导，用于构建个体化压力状态对照；下发 `CMD:X` 取消当前标定或诱导流程，`CMD:R` 重置压力分析引擎，`CMD:E` 清除模型。胸环实时上报 HRV 指标，包括心率、RMSSD、PNN50、LF、HF 和 LF/HF 等；App 根据 STR 状态字段同步未校准、基线校准中、应激诱导中和推理运行中等阶段，并展示平滑压力分数、平静/应激标签和推理次数。该模块为 DBS 闭环控制提供外周生理状态输入。

(4) 实时数据可视化。

实时波形页面采用示波器式深色画布显示多模态生理信号。HRV 胸环侧上行 ECG 数据经解析后进入波形缓冲区，App 以固定刷新节奏绘制滚动 ECG 波形，并根据 RPK 字段标注 R 峰位置，用于观察心搏节律和信号质量。DBS 侧上传的 LFP 流数据由前端 DBS 帧解析模块解码为通道采样点，进入 EEG/LFP 波形缓冲区后通过 Flutter `CustomPainter` 绘制到 CH1 通道；ECG 波形同样由前端波形画布绘制到 CH2 通道。App 同步展示 DBS 采样率、设备状态、电池电量、刺激开关状态和当前参数反馈。HRV 指标、压力分数和 DBS-LFP 波形在同一上位机中汇总，便于观察外周 HRV 变化、压力状态变化和 DBS 刺激反馈之间的关系。

(5) DBS 刺激交互与闭环控制。

App 提供 DBS 刺激交互页面，用于管理刺激启停、刺激强度、刺激频率、脉宽、治疗模式、安全上限和紧急停止。控制模式包括手动模式、HRV 响应模式、LFP 响应模式和混合模式：手动模式下，研究/测试人员可在确认安全条件后解锁并编辑强度、频率和脉宽，并通过 BLE 写特征同步至 DBS；自动模式下，App 侧主要展示算法或下位机反馈的当前参数，并提供安全上限与 E-STOP 入口。App 已支持将压力分数发送给 DBS，用于“HRV/压力评估 - 闭环决策 - DBS 刺激反馈”的链路展示。需要说明的是，App 能够完成参数下发和反馈显示，最终刺激输出由 DBS 端固件执行，硬件端仍是参数合法性校验和刺激安全保护的最终控制点。

(6) 离线 `.mat` 数据测试。

除实时 BLE 模式外，App 还提供独立的离线数据测试功能。用户可导入本地 `.mat` 文件，前端通过 HTTP REST 上传至 FastAPI 后端，后端解析 ECG 数据，提取滤波后波形，完成 R 峰检测和 HRV 指标计算，并将结果返回前端显示。该功能不依赖实时硬件连接，可用于算法验证、比赛演示和实验数据复盘；其输出结果包括 ECG 波形、R 峰数量、心率、RMSSD 等关键指标，与实时数据链路相互补充。

(7) 历史记录与数据归档。

实时采集过程中，系统以登录用户和对象档案为归档入口，将每次采集组织为独立会话。历史记录模块按会话保存 ECG 样本、HRV 记录、压力状态记录、DBS 参数、设备状态和元数据摘要，便于查看采集时长、平均心率、平均 RMSSD、平均压力得分、刺激参数变化和设备信息。该模块与离线数据测试分离：离线测试用于文件导入和算法验证，历史记录用于实时采集会话的归档、检索和趋势回顾。

## 2.4.3 通信协议与数据可视化

App 与外设的通信基于 BLE，采用 Central-Peripheral 架构。App 作为 Central 负责扫描、连接、订阅数据上行特征值并下发控制命令。当前通信链路包括 KT6368A HRV 胸环协议和 DBS 独立 BLE 服务；离线 `.mat` 数据分析通过本地 HTTP REST 接口交由 FastAPI 后端计算。

(1) KT6368A HRV 胸环通信协议。

胸环侧采用自定义 GATT Service，Service UUID 为 `0000FFF0-0000-1000-8000-00805F9B34FB`；Notify Characteristic 为 `FFF1`，用于胸环向 App 上传数据；Write Characteristic 为 `FFF0`，用于 App 向胸环下发控制命令。应用层采用 ASCII 文本包格式，以 `START` 和 `END` 作为包边界，以 `PKTCRC` 字段携带 XOR8 校验值。单个数据包由多行字段组成：

```
START
SYS:mode,source_fs,process_fs,batt_v,batt_pct,charge
ECG:v1,v2,v3,...,vN
RPK:num,idx1,idx2,...,idxN
HRV:rdy60,rdy300,hr,rmssd,pnn50,lf,hf,lf_hf
STR:state,calm_done,calm_need,stress_done,stress_need,score_raw,score_smoothed,is_stressed,infer_count
PKTCRC:XX
END
```

其中，`SYS` 表示设备模式、采样率和电量状态；`ECG` 为批量 ECG 采样点；`RPK` 为当前包内 R 峰数量及位置；`HRV` 为心率变异性指标；`STR` 为压力分析引擎状态和压力得分。App 接收到 BLE 原始字节后，先在缓冲区内寻找完整 `START-END` 数据包，再进行 CRC 校验、字段拆分和数值转换，最后更新全局状态与界面。

(2) HRV 胸环控制命令。

App 通过 Write 特征值向胸环下发 ASCII 控制命令。当前主要命令包括：`CMD:C` 启动基线标定，`CMD:S` 启动应激诱导，`CMD:X` 取消当前标定/诱导流程，`CMD:R` 重置引擎，`CMD:E` 清除模型。命令下发后，App 不直接假定流程完成，而是依据胸环回传的 `STR` 状态字段同步标定阶段、诱导阶段和推理状态，从而保证界面显示与设备端状态一致。

(3) DBS BLE 通信接口。

DBS 设备采用独立 BLE 服务，Service UUID 为 `6E400001-B5A3-F393-E0A9-E50E24DCCA9F`。App 通过 `6E400002-B5A3-F393-E0A9-E50E24DCCA9F` 写特征下发配置和控制帧，通过 `6E400003-B5A3-F393-E0A9-E50E24DCCA9F` 接收设备通知，通过 `6E400004-B5A3-F393-E0A9-E50E24DCCA9F` 接收流数据，通过 `6E400005-B5A3-F393-E0A9-E50E24DCCA9F` 接收存储数据。前端使用 `DbsFrameCodec` 对 DBS 二进制帧进行解码，帧头包含起始字节、标志位、命令字、时间戳、分包信息和数据长度，载荷按 PDU 结构拆分。App 内部将 DBS 帧解析为设备状态、感知配置、刺激参数、运行状态、LFP 流数据和 ACK 事件；其中 LFP 流数据按通道掩码、采样点数量和 16 位有符号采样值解析为通道波形数组。下行命令覆盖状态查询、感知配置查询、刺激参数查询/配置、运行状态查询、运行配置、压力分数发送和刺激启停；上行数据覆盖电量、温度、硬件/固件信息、LFP 采样率、刺激开关状态、当前参数和 LFP 波形样本。

(4) 数据可视化、用户归档与可靠性处理。

实时波形采用前端批量缓冲和定时刷新机制，避免高频 BLE 数据导致界面频繁重绘。ECG 数据保留最近一段时间的滚动窗口，R 峰位置转换为当前窗口内索引后叠加显示；DBS-LFP 数据按 DBS 上报采样率进入独立波形通道，前端每 50 ms 将 LFP 缓冲区刷新到全局波形状态，并保留最近约 10 s 数据。波形画布使用 Flutter `CustomPainter` 绘制网格背景、折线路径和 R 峰标记，能够在不依赖后端服务的情况下完成实时显示。HRV、压力状态、DBS 电量、刺激状态和参数反馈按最新有效上报值更新。协议解析层维护 CRC 成功、失败和缺失统计，DBS 事件流也会将解析异常和加密帧不支持等情况反馈到错误状态，便于联调时判断链路质量。历史记录模块以登录用户和对象档案为归档入口，将每次采集组织为独立会话，并在本地历史记录库中维护 ECG 数据、HRV 指标、压力状态、DBS 参数、设备状态和会话元数据，形成面向科研测试复盘的可回顾、可追溯数据闭环。
