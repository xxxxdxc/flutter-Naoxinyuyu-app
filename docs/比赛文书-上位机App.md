# 2.4 上位机 App 软件设计

## 2.4.1 功能定位与架构

上位机 App 是本作品闭环 DBS 多模态神经调控系统的重要软件成果之一，承担用户登录、设备连接、实时数据展示、参数管理、情绪状态评估、离线数据分析和历史记录管理等人机交互任务。系统面向医生随访、实验联调、参数调整、数据回顾和故障诊断等场景使用。实际闭环运行时，DBS 端可依据预设基础参数与状态评估结果独立完成刺激控制；上位机主要用于可视化监测、参数确认、安全干预和数据分析。

本 App 采用前后端分离的本地架构。前端基于 Flutter 实现跨平台界面，负责用户登录与身份切换、BLE 设备连接、实时波形绘制、HRV 指标展示、情绪状态可视化、DBS 参数控制和历史记录页面；后端基于 Python FastAPI 提供本地计算服务，负责 `.mat` 离线数据解析、ECG 滤波结果读取、R 峰检测、HRV 指标计算和分析结果生成。数据管理层按用户维护历史记录数据库，将采集会话、ECG 片段、HRV 指标、压力/情绪状态、DBS 参数和设备状态与用户身份关联，便于医生按患者维度进行长期随访和回顾。实时硬件通信部分通过 BLE 完成：当前已完成 KT6368A HRV 胸带的数据接入，支持 ECG 波形、R 峰、HRV 指标、电量与压力/情绪状态上报；DBS 侧作为闭环调控对象接入，App 端已设计 DBS 参数控制界面、状态模型和 LFP/刺激状态解析接口，后续可根据 DBS 端最终 BLE 指令集完成实机下发与上行解析联调。

(1) 用户登录与档案管理。

App 引入用户登录入口，用于区分医生、测试人员或患者档案。登录后，系统以用户 ID 作为数据归属主键，将实时采集会话、离线分析结果、HRV 指标、压力/情绪状态和 DBS 参数记录关联到对应用户。该设计避免多名受试者数据混杂，便于医生在随访时快速切换患者档案，查看个人历史趋势和最近一次设备状态。当前 App 已具备默认用户下的历史会话管理能力，后续将进一步完善账号登录、用户档案编辑、身份权限区分和多用户数据索引。

(2) BLE 设备连接与状态管理。

App 作为 BLE Central 扫描并连接目标外设。当前已完成 KT6368A 胸带接入，按照设备广播名和 Service UUID 进行过滤，订阅 Notify 特征值接收实时数据，并通过 Write 特征值下发校准控制命令。界面以设备卡片展示胸带连接状态、电池电量和数据源状态，同时预留 DBS 设备连接入口，为后续 DBS 端 BLE 服务接入提供统一设备管理框架。

(3) ECG 与 DBS-LFP 实时数据展示。

实时波形页面采用示波器式深色画布显示生理信号。胸带侧上行 ECG 数据经解析后进入波形缓冲区，App 以固定刷新节奏绘制滚动 ECG 波形，并根据 RPK 字段标注 R 峰位置，便于观察心搏节律和信号质量。DBS 侧传入信号定义为 LFP 数据，App 端保留 DBS-LFP 上行数据解析与显示接口，可将 DBS 端上传的 LFP 波形、采样率和状态信息纳入同一实时数据视图，用于展示脑区局部场电位变化及其与外周 HRV 指标的联动关系。

(4) HRV 指标与情绪/压力状态可视化。

胸带实时上报 HRV 指标，包括心率、RMSSD、PNN50、LF、HF 和 LF/HF 等。App 在首页和实时数据页同步展示关键指标，并根据设备端 STR 状态字段显示情绪/压力引擎阶段，包括未校准、基线校准中、应激诱导中和推理运行中。用户可在 App 上启动 7 分钟基线校准、启动应激诱导或取消当前流程；完成校准后，App 展示平静/应激状态标签、平滑压力得分和推理次数，用于辅助评估患者当前情绪状态变化。

(5) DBS 刺激参数控制。

App 提供 DBS 参数控制页面，用于展示和管理刺激强度、刺激频率和脉宽等核心参数。控制模式包括手动模式、HRV 响应模式、LFP 响应模式和混合模式：手动模式下医生可解锁并编辑参数；自动模式下参数由闭环算法或下位机控制，App 侧主要用于设置安全上限。系统同时提供紧急停止 E-STOP 入口，在联调和临床安全场景下可快速切换刺激状态。当前 App 端已完成参数编辑、模式切换、安全上限和急停交互设计；待 DBS 端 BLE 指令集确定后，可将界面操作映射为实际刺激参数下发命令。

(6) DBS 上行 LFP 与刺激状态解析。

为支持闭环 DBS 联调，App 端设计了统一的硬件数据结构，用于承载 DBS 上行信息。DBS 端可通过 BLE Notify 上传 LFP 波形、LFP 采样率、DBS 运行状态、电池电量、当前治疗模式、刺激开启/关闭状态以及当前刺激参数反馈。App 解析后将这些字段转换为统一状态，进入实时数据展示、设备状态卡片和分析报告模块。该设计使 HRV 胸带数据与 DBS-LFP 数据可在同一上位机中汇总，为后续“情绪/压力评估 - 闭环决策 - DBS 刺激反馈”的完整链路提供软件接口。

(7) 离线 `.mat` 数据测试与历史记录数据库。

除实时 BLE 模式外，App 还提供离线测试功能。用户可导入本地 `.mat` 文件，前端通过 HTTP REST 上传至 FastAPI 后端，后端解析 ECG 数据，提取滤波后波形，完成 R 峰检测和 HRV 指标计算，并将结果返回前端显示。该功能可在未连接硬件时验证算法流程，也可用于比赛演示和实验数据复盘。实时采集过程中，系统以登录用户为单位维护历史记录数据库，按会话保存 ECG 样本、HRV 记录、压力状态记录、DBS 参数、设备状态和元数据摘要，便于后续查看采集时长、平均心率、平均 RMSSD、平均压力得分、刺激参数变化和设备信息。现阶段 App 已实现本地会话化保存，后续将把会话文件进一步数据库化，形成用户表、采集会话表、HRV 指标表、压力状态表和 DBS 参数表，提升长期随访检索、统计和趋势分析能力。

## 2.4.3 通信协议与数据可视化

App 与外设的通信基于 BLE，采用 Central-Peripheral 架构。App 作为 Central 负责扫描、连接、订阅数据上行特征值并下发控制命令。当前胸带侧已完成 KT6368A BLE 协议对接；DBS 侧按扩展接口设计，支持后续通过 Notify 上报 LFP/状态数据，通过 Write 接收刺激参数与急停命令。

(1) KT6368A 胸带通信协议。

胸带侧采用自定义 GATT Service，Service UUID 为 `0000FFF0-0000-1000-8000-00805F9B34FB`；Notify Characteristic 为 `FFF1`，用于胸带向 App 上传数据；Write Characteristic 为 `FFF0`，用于 App 向胸带下发控制命令。应用层采用 ASCII 文本包格式，以 `START` 和 `END` 作为包边界，以 `PKTCRC` 字段携带 XOR8 校验值。单个数据包由多行字段组成：

```
START
SYS:mode,source_fs,process_fs,batt_v,batt_pct,charge
ECG:v1,v2,v3,...,vN
RPK:num,idx1,idx2,...,idxN
HRV:rdy60,rdy300,hr,rmssd,pnn50,lf,hf,lf_hf
STR:state,calm_done,calm_need,stress_done,stress_need,score_raw,score_smoothed,is_stressed,infer_count
PKTCRC:XX
END
```

其中，`SYS` 表示设备模式、采样率和电量状态；`ECG` 为批量 ECG 采样点；`RPK` 为当前包内 R 峰数量及位置；`HRV` 为心率变异性指标；`STR` 为情绪/压力引擎状态和压力得分。App 接收到 BLE 原始字节后，先在缓冲区内寻找完整 `START-END` 数据包，再进行 CRC 校验、字段拆分和数值转换，最后更新全局状态与界面。

(2) 胸带控制命令。

App 通过 Write 特征值向胸带下发 ASCII 控制命令。当前主要命令包括：`CMD:C` 启动基线校准，`CMD:S` 启动应激诱导，`CMD:X` 取消当前校准/诱导流程，`CMD:R` 重置引擎，`CMD:E` 清除模型。命令下发后，App 不直接假定流程完成，而是依据胸带回传的 `STR` 状态字段同步校准阶段和推理状态，从而保证界面显示与设备端状态一致。

(3) DBS 扩展通信接口。

DBS 端通信设计采用与胸带类似的 BLE Notify/Write 方式。DBS 上行数据用于传输 LFP 波形、刺激器状态、电量、当前模式和参数反馈；DBS 下行命令用于接收刺激强度、频率、脉宽、模式切换、安全上限和 E-STOP 等控制指令。为了降低后续硬件协议变化对前端页面的影响，App 内部将 DBS 上行内容抽象为统一硬件数据包，包含 LFP 波形、LFP 采样率、DBS 运行状态、电池电量和当前模式等字段。最终 DBS 实机联调时，只需将具体字节协议或文本协议映射到该统一数据结构，即可复用现有实时展示、状态管理和参数控制页面。

(4) 数据可视化、用户归档与可靠性处理。

实时波形采用批量缓冲和定时刷新机制，避免高频 BLE 数据导致界面频繁重绘。ECG 数据保留最近一段时间的滚动窗口，R 峰位置转换为当前窗口内索引后叠加显示；HRV 与压力状态按最新有效上报值更新。协议解析层维护 CRC 成功、失败和缺失统计，便于联调时判断链路质量。历史记录模块以登录用户为归档入口，将每次采集组织为独立会话，并在历史记录数据库中维护 ECG 数据、HRV 指标、压力状态、DBS 参数、设备状态和会话元数据，形成面向患者长期随访的可回顾、可追溯数据闭环。
